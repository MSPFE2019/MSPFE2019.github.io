The recipe

Six steps from blank repo to live site

The stack is intentionally simple: semantic HTML, modern CSS, vanilla JavaScript, the public GitHub API, and GitHub Pages.

01

Start a GitHub Pages repository

Create a public repository named YOUR-USERNAME.github.io. A user site with that exact name will be available at the matching github.io address.

Repository nameYOUR-USERNAME.github.io
02

Give GitHub Copilot a precise brief

Describe the audience, visual direction, required data, interactions, states, deployment target, and validation expectations. Strong constraints produce a more complete first implementation.

Prompt tip: Ask Copilot to inspect the repository first, preserve useful content, use the existing stack, and validate the smallest appropriate checks.
03

Fetch repositories at runtime

The site requests public repository data directly in the browser. No build system, database, token, or manual project list is required.

app.js
fetch("https://api.github.com/users/USERNAME/repos" +
      "?per_page=100&sort=updated")
  .then(response => {
    if (!response.ok) throw new Error(response.status);
    return response.json();
  })
  .then(repositories => render(repositories));

Production-ready details matter: paginate results, escape API text before inserting HTML, show loading/error/empty states, cache results briefly, and handle rate limits.

04

Add movement with restraint

This portfolio uses a small canvas particle network, floating capability labels, scroll reveals, a progress indicator, and pointer-responsive card tilt. Everything is written in native browser APIs.

Canvas 2DIntersectionObserverPointer eventsCSS keyframesTheme variables

Always include a prefers-reduced-motion fallback so people who disable motion receive a stable experience.

05

Verify behavior, not just appearance

Run a JavaScript syntax check, serve the site locally, and test the important paths in a browser.

✓Repositories load
✓Search and filters work
✓Empty and error states display
✓Theme preference persists
✓Responsive layouts hold up
✓Reduced motion is respected
06

Push to main and enable GitHub Pages

For a user site repository, publish from the root of the main branch. Add a .nojekyll file when you want GitHub Pages to serve the static files exactly as written.

Live addresshttps://YOUR-USERNAME.github.io/

After deployment, verify the live HTML, CSS, JavaScript, API data, and interactive features—not only the build status.
